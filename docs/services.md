# AWS service documentation

Every service in the architecture is listed below. For each one: its role, why it was chosen over a realistic alternative, how it is configured (with the Terraform file), and what it connects to. Region: `ap-south-1` (Mumbai, the closest region to Bhutan). WAF and ACM for CloudFront live in `us-east-1`.

## Edge and identity

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Amazon Route 53** | DNS for the exam domain | Has an alias record type that points at CloudFront for free and can be managed in Terraform. A registrar's DNS can't alias CloudFront at the zone apex and has no health-checked routing. | Optional `domain_name` + `hosted_zone_id`; A/AAAA alias records to the distribution; DNS validation records for ACM (`edge.tf`) | CloudFront, ACM |
| **Amazon CloudFront** | CDN and single HTTPS entry point: `/` → SPA, `/api/*` → API | Edge caching absorbs the exam-start burst for static files. One domain means no CORS for the API, and WAF attaches here. An ALB would be regional only, with no edge cache, and costs money every hour. | PriceClass_200 (includes India), HTTP/2+3, redirect-to-https, managed SecurityHeaders policy; S3 origin via **OAC**; API origin with a custom no-cache policy that forwards `Authorization`, plus a secret `x-origin-verify` header (`edge.tf`) | Route 53, WAF, S3 frontend, API Gateway, ACM |
| **AWS WAF** | Layer-7 protection at the edge | A managed web ACL is much cheaper to run than self-hosted ModSecurity on EC2, and it blocks bad traffic before it costs Lambda time. | Rule groups: AWSManagedRulesCommonRuleSet, KnownBadInputs, AmazonIpReputationList; rate rule of 2,000 requests per 5 min per IP, with **campus CIDRs exempt** because exam halls share a NAT IP (`edge.tf`) | CloudFront, CloudWatch metrics |
| **AWS Certificate Manager** | TLS certificate for the custom domain | Free, renews automatically, and integrates with CloudFront. Let's Encrypt would need a renewal job and manual import. | DNS-validated certificate in us-east-1; TLSv1.2_2021 minimum (`edge.tf`) | CloudFront, Route 53 |
| **Amazon Cognito** | Sign-in, user directory, role groups | Managed, multi-AZ, with MFA, password policy and a hosted UI, so no auth code to write. Self-built JWT auth on Lambda or Auth0 means more to maintain, or another vendor and its cost. The 10,000-MAU free tier covers all 8,400 users. | User pool with admin-only sign-up; groups `admins`/`tutors`/`students` (precedence 1–3); password ≥ 12 characters; optional TOTP MFA; hosted UI domain; public SPA client using **authorization code + PKCE**; ID/access tokens valid 4 h so a 3-hour exam never expires mid-way (`auth.tf`) | SPA, API Gateway JWT authorizer, λ api (admin user management) |

## Application tier

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Amazon S3 – frontend bucket** | Hosts the static SPA (HTML/JS/CSS) | Static hosting needs no servers and costs pennies. EC2/ECS web servers would have to be patched and scaled for the peak. | Private, Block Public Access, SSE-S3, bucket policy allows only this CloudFront distribution (OAC) and denies non-TLS; objects uploaded by Terraform; `config.js` generated from outputs (`storage.tf`) | CloudFront |
| **Amazon API Gateway (HTTP API)** | REST entry point for the Lambda API | Has a built-in Cognito **JWT authorizer**, is about 70 % cheaper than a REST API, and has lower latency. An ALB would need its own auth and costs money every hour. | Routes `GET /api/health` (public) and `ANY /api/{proxy+}` (JWT, audience = SPA client); stage throttle 1,500 rps / burst 3,000; JSON access logs; Lambda proxy v2 integration to the `live` alias (`compute.tf`) | CloudFront, Cognito, λ api, CloudWatch |
| **AWS Lambda – `api`** | All business logic: exams, attempts, autosave, marking UI, presigned uploads, admin | Scales per request from 0 to thousands in seconds and is billed per millisecond, which suits an exam load that spikes from 300 to 3,000 users. ECS Fargate would need capacity pre-scaled before each exam and costs money every hour. | Python 3.13, arm64 (cheaper, Graviton), 512 MB, 15 s timeout; **in private app subnets in both AZs**; per-function IAM role; X-Ray active; `live` alias with optional **provisioned concurrency** for exam week; rejects requests without the CloudFront origin secret (`compute.tf`, `app/backend/src/api.py`) | API Gateway, Aurora (Data API), S3 uploads, SQS, Cognito, Secrets Manager, KMS |
| **AWS Lambda – `marker`** | Auto-marks MCQs after submission | Runs separately from the request path, so a burst of 3,000 submissions doesn't slow the API. Marking inside the API call would add latency and fail together with it. | 256 MB, 30 s; SQS event source, batch 10, `ReportBatchItemFailures`, **max concurrency 5** to protect the DB; idempotent (`marker.py`) | SQS marking, Aurora |
| **AWS Lambda – `notifier`** | Verifies uploaded files (size, magic bytes), sends emails | Event-driven: it only runs when a file arrives or results are released. Polling S3 on a cron would add delay and waste invocations. | 256 MB, 60 s; SQS event source, **max concurrency 2** (stays under the SES send rate); tags objects `validation=uploaded/rejected`; records `results_emailed_at` so no one gets duplicate emails (`notifier.py`) | SQS notify, S3 uploads, Aurora, SES |
| **AWS Lambda – `migrate`** | Applies the DB schema and seeds demo data on every deploy | Keeps the database reproducible from code (`aws_lambda_invocation`). A manual psql session can't be repeated reliably and needs a bastion host. | Runs during `terraform apply`; idempotent `CREATE … IF NOT EXISTS`; waits up to 4 min for a paused Aurora cluster to resume (`migrate.py`) | Aurora |

## Data tier

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Amazon Aurora PostgreSQL Serverless v2** | System of record: users, exams, questions, attempts, answers, assignments, submissions | Relational data (exam → questions → attempts → answers) suits SQL with constraints. Aurora storage is replicated 6 ways across 3 AZs and fails over in under 60 s. Serverless v2 scales in about 1-second steps for the exam peak and pauses when idle. RDS Multi-AZ fails over more slowly (60–120 s) and has a fixed size; DynamoDB would make tutor reporting queries awkward. | Engine 16.x; **writer in AZ A, reader in AZ B** (promotion tier 1); data subnets with no internet route; SG allows 5432 only from the Lambda SG; storage encrypted with the KMS CMK; `rds.force_ssl=1`; PITR window variable (35 days production, 1 day on the Free-plan lab account); min/max ACU variables (0–4 lab, the Free-plan cap; 2–16 exam week); **Data API enabled** (`database.tf`) | Lambdas (Data API), Secrets Manager, KMS, AWS Backup, CloudWatch |
| **RDS Data API** | HTTPS query interface to Aurora | Lambdas don't open TCP connections, so 3,000 concurrent invocations can't exhaust `max_connections`, and no driver needs packaging. RDS Proxy is the alternative, but it costs extra per vCPU and still needs a driver. | Enabled on the cluster; IAM `rds-data:*` scoped to the cluster ARN; credentials come from Secrets Manager; the client retries on resume and failover (`lib/db.py`) | Aurora, Secrets Manager |
| **Amazon RDS for PostgreSQL, Multi-AZ** *(deployed build)* | Same role as Aurora in the deployed AWS account | The AWS Free plan only allows Aurora in "express configuration" (single instance, outside the VPC, internet-reachable), which would fail the private two-AZ requirement. RDS Multi-AZ keeps the database private and in two AZs within the Free plan. DynamoDB was rejected for the same reporting-query reason as above. | PostgreSQL 17, `db.t4g.micro`, 20 GB gp3; **`multi_az = true` (primary AZ A, synchronous standby AZ B)**; data subnets; SG 5432 from the Lambda SG only; `publicly_accessible = false`; storage encrypted with the KMS CMK; parameter group `rds.force_ssl=1`; backups 1 day (Free-plan cap; 35 in production); PostgreSQL logs to CloudWatch (`database.tf`) | Lambdas (pg8000/TLS), Secrets Manager, KMS, AWS Backup, CloudWatch |
| **Lambda layer – `pg8000` + RDS CA bundle** *(deployed build)* | PostgreSQL driver for the Lambdas | Pure Python, so no native build for arm64; supports the same `:name` parameters as the Data API, so the SQL did not change. psycopg needs compiled binaries. | Built by `scripts/build.sh` from `app/backend/requirements.txt` in deploy.sh and CI; `aws_lambda_layer_version.deps`; one reused TLS connection per Lambda environment, certificate verified against the RDS global CA bundle, reconnect with backoff during failover (`compute.tf`, `lib/db.py`) | All four Lambdas, RDS |
| **Amazon S3 – uploads bucket** | Stores assignment files (PDF/ZIP ≤ 50 MB) for 5 years | Cheaper and more durable (11 nines) than EBS/EFS. **Presigned POST** keeps 50 MB uploads off API Gateway (10 MB limit) and Lambda (6 MB). | Block Public Access, BucketOwnerEnforced, **versioning**, **SSE-KMS** with bucket key, deny non-TLS, CORS for the site origin. **Lifecycle:** 30 d → Standard-IA, 180 d → Glacier Instant Retrieval, 730 d → Deep Archive, **expire at 1,826 d (5 y)**; old versions deleted after 30 d; incomplete multipart uploads aborted after 1 d. `ObjectCreated` → SQS notify (`storage.tf`) | Browser (presigned), λ api, λ notifier, SQS, KMS |
| **AWS Backup** | Independent long-term DB snapshots | Central retention policy kept separate from the cluster, so snapshots survive even if the cluster is deleted. Aurora's built-in backups only go back 35 days, not 5 years. | Vault encrypted with the KMS CMK; plan: daily kept 35 d, **monthly kept 1,826 d**; selection = the database (Aurora cluster in the design, RDS instance in the deployed build) (`backup.tf`) | Aurora / RDS, KMS, IAM |

## Asynchronous processing

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Amazon SQS – `marking` (+ DLQ)** | Buffers submitted attempts for auto-marking | Separates the submit burst from marking and gives retries plus a DLQ for free. SNS has no buffering. EventBridge is not designed for a work queue with throttled consumers. Step Functions would be overkill for one step. | SSE-SQS, long polling 20 s, visibility timeout 180 s (6× Lambda timeout), 4-day retention; redrive to DLQ after 5 receives; DLQ kept 14 d (`async.tf`) | λ api (producer), λ marker (consumer), CloudWatch |
| **Amazon SQS – `notify` (+ DLQ)** | Buffers upload events and "results released" jobs | Same reasons. S3 can deliver events straight to SQS, and the queue smooths email sending to respect SES limits. | Same settings, visibility 360 s; queue policy allows only this bucket (`aws:SourceArn`) and account to send (`async.tf`) | S3 uploads, λ api, λ notifier |
| **Amazon SES** | Sends results-released, new-submission and receipt emails | Pay-per-email, high deliverability, IAM-controlled. SNS email can't be customised per recipient. An SMTP server on EC2 has to be run and has deliverability problems. | Verified sender identity; IAM `ses:SendEmail` limited to that `FromAddress`; sandbox in the lab (production: request production access and add DKIM/SPF on the university domain) (`async.tf`) | λ notifier, students, tutors |

## Networking

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Amazon VPC** | Private network isolating compute and the database | Lambdas and Aurora need private IPs and security groups. The default VPC has only public subnets, which would break the "no public database" rule. | `10.20.0.0/16` across **2 AZs**; per AZ: public `/24`, private app `/24`, private data `/24`; data route table has **no default route** (`network.tf`) | Every regional component |
| **Internet Gateway** | Internet access for the public subnets only | Required for NAT. Nothing else is placed in the public subnets. | Attached to the VPC; public route `0.0.0.0/0` | NAT gateways |
| **NAT Gateway** | Outbound HTTPS from private Lambdas to AWS APIs (Data API, SQS, SES, Cognito, Secrets) | Managed and highly available inside its AZ. A NAT instance would need patching and is a single point of failure. Interface endpoints for 5 services in 2 AZs would cost about $70/month, more than one NAT. | Elastic IP; **one per AZ in production** (`high_availability_nat=true`) with per-AZ route tables; one shared in the lab (`network.tf`) | App subnets, IGW |
| **VPC gateway endpoint (S3)** | Private path from Lambda to S3 | Free, and skips NAT data-processing charges. | Attached to both app route tables (`network.tf`) | λ notifier, λ api, S3 |
| **Security groups** | Stateful firewall per tier | Stateful and reference-based (SG → SG), simpler than NACL rules. | Lambda SG: egress 443 anywhere, 5432 to the DB SG only. DB SG: ingress 5432 from the Lambda SG only (`network.tf`) | Lambda, Aurora |
| **VPC Flow Logs** | Audit of rejected traffic | Needed to investigate security incidents. Packet capture appliances are overkill. | `REJECT` traffic to CloudWatch Logs, 30-day retention (`network.tf`) | CloudWatch Logs, IAM |

## Security, secrets and monitoring

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **AWS Secrets Manager** | Stores DB master credentials and the CloudFront origin secret | Encrypted, audited and rotatable, and the Data API reads it natively. SSM Parameter Store SecureString has no rotation workflow. Plain Lambda environment variables would expose the secret in the console. | Two secrets encrypted with the KMS CMK; access granted per function by ARN; recovery window 0 in the lab, 30 days in production (`security.tf`) | Aurora (Data API), λ api, KMS |
| **AWS KMS (customer-managed key)** | Encryption at rest | A customer-managed key gives automatic rotation, CloudTrail audit of every decrypt, and a key policy we control. AWS-owned keys give none of that, which audits for 5-year exam records need. | Rotation enabled, 7-day deletion window; used by Aurora, S3 uploads, Secrets Manager and the Backup vault (`security.tf`) | Aurora, S3, Secrets Manager, Backup, Lambda |
| **AWS IAM** | Least-privilege access for every component | Native and fine-grained. Shared access keys are the main cause of cloud breaches. | One role per Lambda (DB secret by ARN only; Data API on the cluster ARN only in the Aurora design, S3 on the `submissions/*` prefix only, SES limited to the sender address); flow-logs and backup service roles. CI uses **OIDC roles with no static keys**: deploy role (main branch only) and read-only plan role (PRs) (`compute.tf`, `bootstrap/main.tf`) | Every service |
| **Amazon CloudWatch** | Metrics, logs, alarms, dashboard | Built in to every service used here, with no agent to run. Self-hosted Prometheus/Grafana would be one more thing to operate in exam week. | Log groups with 90-day retention (Lambda, API access logs). **Alarms:** API 5xx ≥ 10/min, p95 latency > 1.5 s, Lambda errors, API throttles, DLQ not empty, marking backlog age > 10 min, database CPU > 80 % and connections > 70 (deployed RDS build; Aurora ACU > 85 % in the design). Dashboard shows API, Lambda, database, SQS and WAF (`monitoring.tf`) | All services, SNS |
| **AWS X-Ray** | Distributed tracing across API → Lambda → AWS SDK calls | Shows where autosave latency comes from with no code changes. Adding an OpenTelemetry collector would mean more infrastructure. | Active tracing on all Lambdas (`compute.tf`) | Lambda |
| **Amazon SNS** | Delivers alarm notifications | Fan-out to email, SMS or chat tools from one topic. | Topic encrypted with `alias/aws/sns`; email subscription to `alarm_email` (`monitoring.tf`) | CloudWatch alarms, admins |

## Delivery (CI/CD and IaC)

| Service | Role | Why over an alternative | Configuration (file) | Connects to |
|---|---|---|---|---|
| **Terraform** | Infrastructure as code for the whole stack | Plans are reviewable, the whole stack can be rebuilt from scratch, and it handles CloudFront/WAF in us-east-1 alongside ap-south-1. Console clicks can't be reproduced. CloudFormation/SAM is AWS-only and more verbose. | `infra/*.tf`, AWS provider 5.x, S3 remote state with native lockfile, partial backend config; variables for lab vs production | All AWS services |
| **Amazon S3 – Terraform state** | Shared, versioned state for local and CI runs | Versioning allows recovering a corrupted state; S3 native locking means no DynamoDB table is needed. Local state can't be shared with CI. | Versioned, SSE-S3, Block Public Access, deny non-TLS (`infra/bootstrap`) | Terraform, GitHub Actions |
| **GitHub Actions** | CI/CD: test → plan (PR) / apply (main) | It is where the code lives and is free for this usage. CodePipeline + CodeBuild would add more AWS resources and cost. | `.github/workflows/deploy.yml`: Python unit tests, JS syntax check, `terraform fmt`; on PR `plan` with the read-only role; on push to main `apply`, CloudFront invalidation, `/api/health?deep=1` smoke test | IAM OIDC, Terraform |
| **IAM OIDC provider + STS** | Short-lived AWS credentials for GitHub Actions | No long-lived access keys stored in GitHub. | Trust limited to `repo:<owner>/<repo>:ref:refs/heads/main` (deploy) and `:pull_request` (plan) (`infra/bootstrap/main.tf`) | GitHub Actions, IAM |
